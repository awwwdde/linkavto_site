# Настройка VIN, госномеров, поиска, кроссов и аналогов

Документ описывает, как в проекте подключены:

- поиск по VIN автомобиля;
- поиск по госномеру автомобиля;
- VIN при добавлении автомобиля в гараж;
- VIN при добавлении товара продавцом;
- поиск по артикулам;
- кроссы, OEM-номера, замены и подбор аналогов.

## 1. Общая схема

В проекте используются две разные VIN-сущности:

- `garage.Vehicle.vin` - VIN автомобиля пользователя в гараже;
- `shop.Product.vin` - VIN, указанный у товара/запчасти.

Поиск по VIN/госномеру автомобиля работает через гараж пользователя:

1. Пользователь добавляет автомобиль в гараж.
2. VIN и госномер нормализуются и сохраняются.
3. Пользователь вводит VIN или госномер в поиск.
4. Сервис поиска находит активный автомобиль пользователя.
5. По найденному автомобилю подбираются совместимые товары.

Поиск по артикулам, кроссам и аналогам работает через товары и таблицу `ProductCrossReference`:

1. У товара есть основной артикул `Product.part_number`.
2. Для быстрого поиска хранится нормализованный артикул `Product.normalized_part_number`.
3. Кроссы и аналоги хранятся в `ProductCrossReference`.
4. Поиск сравнивает введенный номер с основными артикулами и кросс-номерами.
5. В выдачу попадают основной товар, связанные кроссы и товары-аналоги.

## 2. Модель товара и кроссы

Файл: `shop/models.py`

### `normalize_article_number(value)`

Функция приводит артикул к единому виду:

- переводит в верхний регистр;
- убирает пробелы, дефисы, слеши и другие разделители;
- оставляет только буквы и цифры.

Пример:

```text
OC-90
oc 90
OC/90
```

Все эти варианты будут сравниваться как `OC90`.

### `Product.normalized_part_number`

Служебное поле товара для нормализованного артикула.

Что делает:

- заполняется автоматически при `Product.save()`;
- индексируется в базе;
- используется для быстрого поиска по артикулу без зависимости от написания.

### `ProductCrossReference`

Модель для кроссов и аналогов товара.

Основные поля:

- `product` - товар, для которого добавлен кросс;
- `article_number` - исходный кросс-номер;
- `normalized_article` - нормализованный кросс-номер;
- `brand` - бренд/производитель кросса;
- `relation_type` - тип связи;
- `analog_product` - товар-аналог в каталоге, если он есть;
- `is_active` - активность связи.

Типы связи:

- `cross` - кросс-номер;
- `analog` - аналог;
- `oem` - оригинальный/OEM-номер;
- `replacement` - замена.

## 3. Миграция базы

Файл: `shop/migrations/0015_product_cross_references.py`

Миграция делает три вещи:

1. Добавляет поле `Product.normalized_part_number`.
2. Заполняет это поле для существующих товаров.
3. Создает таблицу `ProductCrossReference`.

После установки изменений нужно выполнить:

```bash
python manage.py migrate
```

## 4. Админка кроссов

Файл: `shop/admin.py`

В админке добавлено:

- редактирование кроссов прямо в карточке товара;
- отдельный раздел для `ProductCrossReference`;
- поиск товаров по нормализованному артикулу и кросс-номерам.

Это нужно, чтобы менеджер мог вручную связать товар с OEM-номерами, заменами и аналогами без импорта файла.

## 5. Импорт кроссов

Файл: `shop/management/commands/import_cross_references.py`

Команда импортирует кроссы из CSV или Excel.

Пример:

```bash
python manage.py import_cross_references crosses.csv
```

Проверка без записи:

```bash
python manage.py import_cross_references crosses.csv --dry-run
```

Поддерживаемые колонки:

- `product_article`, `part_number`, `product_part_number` - артикул основного товара;
- `cross_article`, `article_number`, `cross_number` - кросс-номер;
- `brand`, `manufacturer` - бренд кросса;
- `relation_type`, `type` - тип связи;
- `analog_article`, `analog_part_number` - артикул товара-аналога;
- `analog_product_id` - ID товара-аналога;
- `comment`, `note` - комментарий.

Команда ищет основной товар по `Product.normalized_part_number`, затем создает или обновляет `ProductCrossReference`.

## 6. Поиск

Основной файл: `search/services.py`

### Определение типа запроса

`SearchService.detect_search_type(query)` определяет:

- `vin` - VIN автомобиля;
- `license_plate` - госномер;
- `part_number` - артикул;
- `text` - обычный текстовый поиск.

VIN и госномера предварительно нормализуются.

### Поиск по VIN автомобиля

Работает для авторизованного пользователя.

Поток:

1. Пользователь вводит VIN.
2. `SearchService` находит активный `garage.Vehicle` с таким VIN у текущего пользователя.
3. По найденному автомобилю строится фильтр совместимости.
4. В выдачу попадают товары для подходящей марки, модели, поколения и модификации.

Важно: это не внешний VIN-декодер. Поиск работает по тем автомобилям, которые уже есть в гараже пользователя.

### Поиск по госномеру

Работает аналогично VIN:

1. Госномер нормализуется.
2. Русские буквы, похожие на латинские, приводятся к единому виду.
3. Ищется автомобиль пользователя в гараже.
4. По найденному автомобилю подбираются совместимые товары.

### Поиск по артикулам, кроссам и аналогам

Порядок релевантности:

1. Точные совпадения по названию, артикулу, VIN товара и кроссам.
2. Связанные товары через `ProductCrossReference`.
3. Совместимые товары по автомобилю из гаража.
4. Нечеткий поиск.
5. Fallback-поиск по названию, описанию, артикулу, VIN и кроссам.

## 7. Нечеткий поиск и автоподсказки

Файл: `search/fuzzy_search.py`

Нечеткий поиск использует `rapidfuzz`.

Учитываются:

- название товара;
- артикул товара;
- нормализованный артикул;
- VIN товара;
- кросс-номера;
- аналоги.

Автоподсказки возвращают подсказки по:

- VIN;
- артикулу;
- названию;
- кроссам.

Для кроссов используется тип подсказки `cross_reference`.

## 8. Страницы поиска

Файлы:

- `search/views.py`;
- `shop/views.py`;
- `search/templates/search/autocomplete.html`;
- `shop/templates/shop/search.html`.

Что подключено:

- в поиск передается `request.user`, чтобы VIN/госномер могли искать автомобиль в гараже;
- в контекст передается `search_type`;
- добавлен флаг для отображения поиска по госномеру;
- подсказки используют `data-value`, чтобы при клике в строку поиска попадал чистый артикул/кросс, а не весь текст подсказки;
- сортировка по дате по умолчанию убрана, чтобы не ломать релевантность `SearchService`.

## 9. VIN в гараже

Файлы:

- `garage/services.py`;
- `garage/models.py`;
- `garage/forms.py`;
- `garage/views.py`;
- `garage/templates/garage/add.html`.

### Нормализация VIN

`VINService.normalize_vin(vin)`:

- переводит строку в верхний регистр;
- заменяет похожие русские буквы на латинские;
- убирает пробелы, дефисы и другие разделители;
- оставляет только буквы и цифры.

Например:

```text
хта 21093-123456789
```

будет приведено к нормализованному виду перед проверкой и сохранением.

### Валидация VIN

`VINService.validate_vin(vin)` проверяет:

- VIN не пустой;
- длина ровно 17 символов;
- используются допустимые символы;
- нет запрещенных букв `I`, `O`, `Q`;
- для североамериканских VIN проверяется контрольная сумма.

### Добавление автомобиля в гараж

При добавлении автомобиля:

1. VIN нормализуется на клиенте.
2. VIN проверяется через `/garage/api/validate-vin/`.
3. Если VIN корректный, он сохраняется в `Vehicle.vin`.
4. Если год не указан, система пытается определить год из VIN.
5. Если такой активный VIN уже есть у пользователя, добавление блокируется.

### Админка гаража

Форма админки также использует нормализацию VIN. Это защищает от ручного ввода VIN в разном формате.

## 10. VIN на странице продавца `/sellers/products/add/`

Файлы:

- `sellers/views.py`;
- `sellers/templates/sellers/add_product.html`;
- `garage/services.py`.

### Поле VIN товара

На странице добавления товара поле `vin_number` сохраняется в `Product.vin`.

Что настроено:

- можно вставлять VIN с пробелами и дефисами;
- русские похожие буквы заменяются на латинские;
- поле приводится к верхнему регистру;
- перед отправкой формы проверяется длина 17 символов;
- сервер повторно нормализует и валидирует VIN;
- неверный VIN блокирует сохранение товара.

### API `/sellers/api/vin-info/`

Endpoint используется страницей добавления товара для подсказки по VIN.

Сейчас он работает так:

1. Нормализует VIN через `VINService`.
2. Проверяет VIN.
3. Пытается использовать внешний/оптимизированный декодер `vehicles.vin_decoder`, если он когда-нибудь появится в проекте.
4. Если декодера нет, безопасно переходит на fallback.
5. Fallback ищет существующие товары с таким VIN и берет из них данные совместимости.
6. Если точных данных нет, пытается определить возможную марку по WMI.

Важно: отсутствующий модуль `vehicles.vin_decoder` больше не должен ломать endpoint.

## 11. Совместимость товаров с транспортом

Модель `Product` уже содержит поля совместимости:

- `vehicle_type`;
- `car_brand`, `car_models`, `car_generations`, `car_modifications`;
- `truck_brand`, `truck_models`, `truck_generations`, `truck_modifications`;
- `moto_brand`, `moto_models`, `moto_generations`, `moto_modifications`;
- `special_brand`, `special_models`, `special_generations`, `special_modifications`.

Поиск по автомобилю из гаража использует эти поля.

Если у автомобиля указана только марка, поиск будет работать шире. Если указаны модель, поколение и модификация, подбор будет точнее.

## 12. Что нужно для запуска после установки

1. Применить миграции:

```bash
python manage.py migrate
```

2. Наполнить кроссы:

```bash
python manage.py import_cross_references crosses.csv
```

3. Проверить в админке, что у товаров заполнены:

- артикул;
- кроссы;
- совместимость с транспортом;
- VIN товара, если нужен.

4. Проверить гараж:

- добавить автомобиль с VIN;
- добавить госномер;
- выбрать марку/модель/поколение/модификацию.

5. Проверить поиск:

- поиск по VIN автомобиля из гаража;
- поиск по госномеру автомобиля из гаража;
- поиск по основному артикулу;
- поиск по кросс-номеру;
- поиск по товару-аналогу.

## 13. Ограничения

Поиск по VIN и госномеру автомобиля не расшифровывает номер через внешний государственный или коммерческий сервис.

Сейчас логика такая:

- VIN/госномер ищется среди автомобилей пользователя в гараже;
- подбор товаров идет по уже сохраненной совместимости автомобиля;
- для публичного распознавания VIN или госномера нужен отдельный внешний API или база соответствий.

Кроссы и аналоги начинают работать полноценно только после наполнения таблицы `ProductCrossReference`.
